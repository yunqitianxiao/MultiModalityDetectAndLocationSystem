/odom + /imu ──①导航状态──> 12维 pose_state ──④嵌入──> 128维 pose_embedding

## ① 导航状态来源（ROS2 odom/IMU → 12 维向量）

`pose_state_node.py` 把 `/odom` + `/imu` 合成 12 维 `[x,y,z, sin/cos roll, sin/cos pitch, sin/cos yaw, vx, vy, wz]`。
要读懂它，需要下面这些。

| 教程 | 链接 | 为什么需要 |
|---|---|---|
| ROS2 TF2 坐标系（odom/base_link/map） | <https://docs.ros.org/en/humble/Tutorials/Intermediate/Tf2/Tf2-Main.html> | 世界系→车体系的变换链，定位链（里程/环号/时钟方位）的坐标系基础 |
| `nav_msgs/Odometry` 消息定义 | <https://docs.ros.org/en/humble/p/nav_msgs/msg/Odometry.html> | 车的位置+姿态四元数+线/角速度——12 维里 x/y/z/yaw/vx/vy/wz 的来源 |
| `sensor_msgs/Imu` 消息定义 | <https://docs.ros.org/en/humble/p/sensor_msgs/msg/Imu.html> | IMU 的 roll/pitch 补 odom 缺失；200Hz 高频来源 |
| robot_localization（odom+IMU EKF 融合） | <https://docs.ros.org/en/humble/p/robot_localization/> | 理解"为什么 odom 给 yaw、IMU 给 roll/pitch，拼起来才是完整姿态" |
| ros_gz_bridge（仿真桥接） | <https://github.com/gazebosim/ros_gz> | gz 侧 `/odom` `/imu` 怎么进 ROS 侧（对应 `config/ros_gz_bridge.yaml`） |
| Gazebo Harmonic 传感器文档 | <https://gazebosim.org/docs/harmonic/sensors/> | imu/lidar/camera 传感器怎么在仿真里生成数据 |

**对应项目文件**：`scripts/pose_state_node.py`、`scripts/odom_tf_broadcaster.py`、`config/ros_gz_bridge.yaml`、`README.md §5（话题）/ §6（TF树）`。

## ② 真实部署定位：FAST-LIO2（雷达+IMU 紧耦合里程计）

仿真里 `/odom` 由 Gazebo DiffDrive 给出；**真实隧道里没有这回事**，用 FAST-LIO2 从雷达点云+IMU 实时算出里程。
它是 `/pose_state` 的时序源头——所以编码器用逐帧 MLP 而不是 RNN（时序已在里程计解好）。

| 教程 | 链接 | 说明 |
|---|---|---|
| FAST-LIO2 官方仓库 | <https://github.com/hku-mars/FAST_LIO> | 直接 iSAM2 增量式紧耦合，比 FAST-LIO 更快，隧道这类退化环境关键 |
| FAST-LIO2 论文 | <https://arxiv.org/abs/2210.17343> | 想深挖再读；跑起来不用 |

**对应项目文件**：`worlds/inspection_tunnel.world` 的 `/lidar/points`（16 线 gpu_lidar）+ `/imu` 即其输入。

## ③ 相机-雷达联合标定（2D 像素 ↔ 3D 点云的前提）

空间语义映射的核心：`像素(u,v)+深度 → 相机系(K⁻¹) → 车体系(T_cam_base) → 世界系`。
深度来自把雷达点投进图像框取中值。这套变换全靠标定参数，不需要配对训练数据。

| 教程 | 链接 | 为什么需要 |
|---|---|---|
| OpenCV 针孔相机标定 | <https://docs.opencv.org/4.x/dc/dbb/tutorial_py_calibration.html> | 内参 K 从哪来，`像素→相机系` 的数学（对应 `img_px_to_world.py` 的 `pixel_to_world`） |
| Camera-LiDAR 外参标定（经典仓库） | <https://github.com/hengruojp/Camera-LiDAR-Calibration> | 外参 T_cam_base / T_lidar_base 从哪来（对应 `传感器参数.py`） |
| easy_handeye（手眼标定，仿真标定板用） | <https://github.com/ros-drivers/easy_handeye> | README §7 推荐的联合标定流程 |

**对应项目文件**：`传感器参数.py`（相机/雷达/IMU 外参 + 隧道几何）、`urdf/inspection_robot.urdf.xacro` 顶部传感器位姿参数、`img_px_to_world.py`。

## ④ 一维位姿序列嵌入（"1D 技术"核心）

`/pose_state` 是 **T×12** 的一维时序。做法：**逐帧** MLP 编码成 128 维嵌入（不用 RNN——时序由 FAST-LIO2 解好），
自监督代理任务 = 预测**下一帧状态增量**，让编码器学会"状态在怎么变"。之后嵌入通过 FiLM 条件化 YOLO 的 P3/P4/P5 特征。

| 教程 | 链接 | 为什么需要 |
|---|---|---|
| d2l 动手学深度学习（序列部分，中文） | <https://zh.d2l.ai/chapter_recurrent-neural-networks/> | 一维时序怎么变成特征向量；也解释了为什么这里用 MLP 而非 RNN |
| The Illustrated Transformer（sin/cos 位置编码） | <https://jalammar.github.io/illustrated-transformer/> | 为什么 yaw 用 sin/cos 而不是裸角度——角度有 2π 跳变，sin/cos 连续 |
| FiLM 论文（特征线性调制） | <https://arxiv.org/abs/1709.07871> | 下一步多模态融合：128 维嵌入怎么条件化图像特征（方案选型） |
| PyTorch 张量/MLP 入门 | <https://pytorch.org/tutorials/beginner/introyt/tensors_deeper_tutorial.html> | 读懂 `pose_mlp.py` 的层与训练脚本 |

**对应项目文件**：`data_gen/pose_mlp.py`（模型）、`scripts/train_pose_encoder.py`（训练）、`scripts/pose_encoder_node.py`（在线部署）。
训练数据：真实采集用 `pose_state_node.py --ros-args -p log_csv:=xxx.csv`；没有真实数据时用合成轨迹。

## 建议阅读顺序

**按管线（先搭框架再补细节）**：

```
1. ① TF2 坐标系         —— 看懂"车在世界里怎么定位"的框架
2. ① 两个消息定义        —— 看懂 /odom /imu 里到底有什么
3. ③ 相机标定（内参）    —— 看懂"像素→3D"第一步
4. ④ sin/cos + MLP 嵌入  —— 看懂 pose_state 怎么变成 pose_embedding
5. ② FAST-LIO2          —— 真实部署前再看
```

**按角色**：
- 做**仿真数据/传感器** → ① 全部 + ③ easy_handeye
- 做**定位/里程** → ② FAST-LIO2 + ① robot_localization
- 做**多模态检测/融合** → ③ 标定 + ④ 嵌入/FiLM
- 做**空间语义映射**（病害在隧道的里程/环号/方位）→ ③ 全部 + ④

## 附：一条命令打通嵌入链路（验证教程所学）

```bash
source setup.sh
# 1) 启动仿真(需要车不翻车, 见下注)
ros2 launch inspection_robot inspection_robot.launch.py headless:=true use_rviz:=false
# 2) 启动 12 维状态合成 + 128 维嵌入(加载训练好的权重)
ros2 run inspection_robot pose_state_node.py &
ros2 run inspection_robot pose_encoder_node.py --ros-args -p ckpt:=/home/ylf/pose_mlp_tunnel.pt &
# 3) 看嵌入输出
ros2 topic echo /pose_embedding --once
```

> ⚠️ **注意**：当前训练好的权重 `/home/ylf/pose_mlp_tunnel.pt` 是**合成轨迹**训练的基线。
> 本机仿真车存在 spawn 即翻车（roll=180°）的稳定性 bug，真实 `/pose_state` 采集不可用；
> 待车物理修好后，用 `train_pose_encoder.py --csv <真实CSV>` 重训即可，代码路径不变。
